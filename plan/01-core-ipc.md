# Phase 01 — Core IPC

## Hypothesis

A sidecar process boundary using a Unix Domain Socket and Vela-owned JSON messages can provide reliable bidirectional streaming, cancellation, and lifecycle isolation between Swift and Rust.

## Objectives

- Launch/supervise `vela-core` from the macOS app.
- Establish versioned local IPC.
- Support request/response and server-pushed events.
- Prove streaming and cancellation before introducing ACP.
- Define crash/reconnect semantics.

## Scope

### Protocol

Minimum messages:

```text
core.hello
core.health
stream.start
stream.cancel
```

The test stream should be generated by Vela Core itself and must not depend on an LLM or network.

### Process lifecycle

The app should:

- locate the bundled/development core executable;
- launch it;
- detect readiness;
- detect unexpected exit;
- show degraded state instead of hanging;
- restart explicitly or automatically according to documented policy.

### Streaming

Core emits deterministic text/event chunks at controlled intervals so ordering, UI rendering, cancellation, and disconnect behavior are observable.

## Non-goals

- ACP.
- Agent-specific events.
- Workspace writes.
- Authentication.
- Live2D.

## Deliverable

A native debug screen can connect to Vela Core, start a deterministic stream, render incremental events, cancel it, kill the core process, and recover without restarting the macOS app.

## Acceptance Criteria

- [ ] App launches and establishes IPC with Core.
- [ ] Protocol handshake includes a version and rejects incompatible major versions.
- [ ] Request IDs correlate responses and errors.
- [ ] Core can push multiple ordered events for one request.
- [ ] Cancellation stops the stream and yields a terminal cancellation event.
- [ ] App remains responsive when Core is killed mid-stream.
- [ ] Core restart/reconnect works without relaunching the app.
- [ ] Malformed JSON/message input returns a protocol error and does not crash Core.
- [ ] A connection loss is surfaced in diagnostics with correlation/context data.
- [ ] Integration tests cover stream success, cancel, malformed input, and disconnect.

## Validation Procedure

1. Launch app and Core.
2. Run a 20-event synthetic stream.
3. Cancel after several events and verify no post-terminal events are accepted.
4. Start another stream and terminate Core externally.
5. Recover Core and start a new stream.
6. Inject one malformed frame with a test client.

## Evidence to Capture

- IPC schema version.
- Lifecycle state diagram.
- Integration-test output.
- Logs for normal cancel and abnormal Core exit.
- Any measured reconnect latency relevant to UX.

## Exit Decision

Do not add ACP until process supervision and streaming behavior are deterministic. If IPC proves awkward, change the transport now while no product domain depends on it.
