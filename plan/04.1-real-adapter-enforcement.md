# Phase 04.1 — Real Adapter Enforcement

## Hypothesis

Vela can prevent a real ACP adapter from executing a mutation unless the adapter is first placed in a Vela-selected safe session mode and the resulting permission request is mediated by Vela.

## Objectives

- Pin every built-in and user-defined adapter to an explicit ACP session mode.
- Reject session creation before the first prompt when that mode cannot be verified and set.
- Prevent ambient provider settings from silently selecting an auto-approval or full-access mode.
- Prove the boundary with disposable real-provider write attempts and retained permission audit records.

## Scope

- `codex-acp`: launch in `read-only`, `on-request`, user-reviewed mode with network disabled and temporary roots excluded from any workspace-write fallback.
- `claude-agent-acp`: set ACP session mode to `default` after `session/new` and before the session becomes ready.
- Custom ACP harnesses: require `enforced_session_mode`; optionally pass non-secret launch environment overrides.
- Surface the enforced mode in `AgentDescriptor` and native diagnostics.
- Provide a repeatable smoke runner that denies one write in an isolated `/private/tmp` workspace and verifies zero mutation.

## Non-goals

- Persisting provider-wide permission settings.
- Treating provider `allow_always` as a Vela session grant.
- Automatically approving the real-adapter probe.
- Supporting adapters that do not implement ACP session modes.

## Deliverable

A Vela session becomes ready only after its adapter advertises and accepts the required ACP mode. Both installed real adapters must emit a Vela-brokered `filesystem.write` request for a disposable write probe; denial must be audited and the target must remain absent.

## Acceptance Criteria

- [x] Adapter child-process environment overrides are owned by the Rust launch spec.
- [x] `session/new` must advertise the configured mode.
- [x] Vela sends `session/set_mode` before publishing session readiness.
- [x] Missing modes, unsupported modes, and rejected mode changes all fail closed before a prompt.
- [x] Codex is pinned to `read-only`, `on-request`, and `approvals_reviewer=user`.
- [x] Claude is pinned to `default`, overriding an escalating initial permission mode before any prompt.
- [x] Discovery and the Swift diagnostics surface `enforced_session_mode`.
- [x] Custom harness definitions without a non-empty `enforced_session_mode` are rejected.
- [x] Real Codex and Claude probes both reach Vela's broker, are denied, retain audit evidence, and leave no file behind.
- [x] The deterministic Rust, Swift, and Swift↔Rust suites remain green.

## Validation Record — 2026-08-25

The repeatable command is:

```bash
node scripts/real-adapter-enforcement-smoke.mjs codex
node scripts/real-adapter-enforcement-smoke.mjs claude
```

Each invocation creates a unique `/private/tmp/vela-real-enforcement-*` directory, starts Vela Core, discovers the real adapter, creates a session in the required mode, and asks its native edit/write tool to create one file. The runner immediately denies the first `filesystem.write` request, verifies the audit record is `denied`, verifies the target is absent, terminates Core and adapter processes, and removes the whole temporary directory.

| Adapter | Version | Enforced mode | Broker result | Mutation |
|---|---:|---|---|---|
| `codex-acp` | 1.6.2 | `read-only` | `filesystem.write` → `deny` → audited `denied` | target absent |
| `claude-agent-acp` | 0.70.0 | `default` | `filesystem.write` → `deny` → audited `denied` | target absent |

Codex initially performed an internal Guardian denial before emitting ACP permission. Adding the explicit `approvals_reviewer=user` launch baseline caused the same safe probe to surface through `session/request_permission`; this setting is therefore part of the enforced built-in contract, not merely test configuration.

## Exit Decision — Gate A

**Pass.** Vela now discovers, controls, observes, and safely mediates the installed local ACP runtimes. Deterministic tests cover broker behavior and fail-closed mode negotiation; disposable real-provider probes prove both installed adapters cannot perform the tested write without crossing the Vela broker.

Proceed to Phase 05 — Local-First Workspace.
